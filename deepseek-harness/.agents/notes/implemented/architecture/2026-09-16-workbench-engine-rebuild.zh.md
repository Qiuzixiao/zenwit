# Agent Note：工作台引擎重建

Status: implemented

[English](2026-09-16-workbench-engine-rebuild.md) | 中文

## 问题

产品的文件管理与编辑器原本是内核内的一份实现：文件树是对整个项目的一次扫描，只靠渲染预算设限；搜索在浏览器里对那棵已被截断的树做过滤；没有变更/Git 视角、没有终端、没有浏览器，模型也无法把文件放到屏幕上。项目一大，用户看到的就是一棵被截断的树和搜不到东西的搜索框。

产品想要的能力水准，社区插件里已经有了。但把它作为 profile 插件引入，会让产品的核心文件能力变成第三方的运行时依赖，在产品自己的工作台根之外多出第二个工作台根，而且无法绑定产品的项目库。

## 决定

产品自己实现引擎，并删除原先那份实现。

- **宿主半**放在 `zenwit-workspace`（`src/workbench/`）：单层目录列举、原子读写/改名/删除/上传、宿主端文件名搜索、工作区包含判定与 Host 头信任围栏、Git，以及一个方法接口 `/api/desktop/workbench`（JSON 信封：`{ method, project, … }`）、流式上传路由、媒体字节流与沙箱 HTML 预览路由。**项目作用域取代来源插件的会话作用域**：每个方法都要点名一个项目库已登记的目录，包含判定再对解析后的目标复核一次。
- **客户端半**放在 `ui-workbench/src/client/workbench/`：资源管理器、可拖拽分屏的标签条、编辑器宿主、预览、变更与 diff 视图、终端、浏览器、任务页与侧边对话。它是本包自己的源码，改名并换上内核的 `--dsw-*` 语义 token，文案进内核语言字典。
- **面板座位**沿用[首页面板导航](2026-09-15-home-surface-panel-navigation.zh.md)的决定（同一份列表、同一套选中逻辑）；工作区把选中的面板渲染在**引擎区域的位置**，而不是叠在保留的编辑器之上——那个区域现在归引擎。
- **三栏**：工作区保留它一直有的三栏（资源管理器 / 引擎区域 / 对话）。引擎的资源管理器以组件形式提供（`ExplorerPane`，即移植过来的文件树面板），由外壳放进左栏，数据来自 `apply()` 返回的 store —— 于是左栏与中栏是同一个工作台；该面板按项目工作，因此还没有对话时也能列出当前项目。
- **挂载约定**：工作区外壳渲染一个区域（`[data-zenwit-workbench-surface]`）；引擎把自己的 React 根挂进去并标记为嵌入（`embedded` 标记一路传到 `Workbench`）。嵌入模式下引擎填满该区域：面板不取视口几何，中列定位器完全不运行（因此不会给对话列打上 `data-dsh-center-col`、也不会有布局挤压），折叠控件与高度拖拽条一并隐藏——面板已经独占整个区域。没有这个区域时引擎保留自带的全视口浮层与中列跟踪，可独立运行。
- **样式表身份**：客户端打包预设按样式表在包内 `src` 目录下的路径给每个注入的 `<style>` 命名。引擎的 `workbench/workbench.module.css` 与外壳的 `workbench.module.css` 同名，而旧标识丢掉了目录——注入守卫因此跳过第二张表，引擎渲染成无样式。
- **插件连续性**：[文档渲染器注册表](2026-09-13-document-renderer-registry.zh.md)作为贡献契约保留，并新增 `declarations()` 读取；`renderer-bridge.ts` 把每个按扩展名匹配的声明镜像进引擎的预览器注册表，贡献过预览视图的插件无需改动即可继续工作。
- **聊天的文件链接**经 `ctx.workbenchFiles.openFile` 落到引擎的编辑器标签。

## 结果

- `Workspace.tsx` 从约 1350 行缩到约 166 行：它只声明引擎区域并负责对话列的几何；文档生命周期归引擎。
- 引擎的宿主半由 `zenwit-workspace` 自己的测试覆盖（文件系统、Git、搜索、预览路由）；本包的测试覆盖注册、外壳、桥接与项目接口。
- 客户端产物现在带着编辑器、终端与图表三套依赖，因为内核每个包只产出一个动态包；恢复逐视图懒加载需要拆分的构建产物与宿主分片路由。
- 桥接只镜像声明了文件扩展名的渲染器；只声明媒体类型的要等引擎侧的嗅探。
- 模型主动打开文件由宿主提供（桌面包的 `workbench_open`）。**模型终端视图不属于本引擎**：模型跑命令的能力已由内核自带终端工具提供，而移植来的那套视图需要终端服务提供「输出订阅」与「等待取消」两项当前没有的能力，因此整体移除，而不是留着一个永远不工作的入口。
- 在产品外壳里引擎以整区域面板渲染，因此它的空状态就是面板自己的"可打开类型"卡片；希望打开即有标签的部署可通过 `ctx.workbenchEngine.openTab` 先开一个。

## 考虑过的替代方案

**把社区插件作为 profile 插件发布。** 否决：它让文件能力成为第三方运行时依赖，挂载第二个工作台根，且无法绑定项目库。

**保留旧实现并在其上补功能。** 否决：整项目扫描是它的架构而非可以打补丁的缺陷；搜索、懒加载层级与变更视角都源自替换它。
